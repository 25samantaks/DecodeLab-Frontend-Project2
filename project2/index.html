01 · THE FOUNDATION

Mobile-first strategy

Start with the smallest screen, then progressively enhance the experience.

01

Mobile First

The base stylesheet is designed for phones first. Larger screens add space and layout complexity only when the viewport can support it.

base → 48rem → 70rem
02

Breakpoints are bridges, not fences

Breakpoints are chosen when the content needs more room—not because a particular device happens to exist.

03

Fluid by default

Percentages, rem, minmax(), clamp() and viewport-aware spacing keep the page comfortable between breakpoints.

03 · FLUID TYPOGRAPHY

Type that breathes with the viewport.

Responsive typography should not suddenly jump between sizes. The CSS clamp() function lets text scale smoothly.

/* Fluid, not fixed */ .hero h1 {   font-size:   clamp(2.8rem, 8vw, 7rem); } /* Spacing adapts too */ .section {   padding-block:   clamp(4rem, 10vw, 9rem); }

04 · BRACKET NAVIGATION

Navigation that opens where you need it.

This project uses the native Popover API for the compact mobile menu. It keeps the markup semantic and reduces the amount of JavaScript required for basic menu behavior.

  • Clear focus states

06 · FUTURE-PROOFING THE WEB

Build systems that can adapt to what comes next.

Avoid unnecessary fixed dimensions. Prefer semantic HTML, modern CSS, progressive enhancement and resilient components. The goal is not to predict every screen—it is to build a layout that can respond to change.

Why mobile-first?

It keeps the foundation simple and lets larger screens progressively gain features and space.

Grid or Flexbox?

Use Grid for two-dimensional page structure and Flexbox for one-dimensional component alignment.

Why use clamp()?

It creates fluid values between a minimum and maximum, reducing abrupt jumps across screen sizes.

What makes this project accessible?

Semantic HTML, skip navigation, focus styles, readable contrast, scalable units, touch-friendly controls and reduced reliance on JavaScript.
